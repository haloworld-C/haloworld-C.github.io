引子：EVA初号机不是普通机甲

最近思考大模型 Agent 与软件运行时的关系时，我经常联想到《新世纪福音战士》中的 EVA 初号机。

初号机并不是一台单纯等待驾驶员操纵的机器。严格按作品设定，它由莉莉丝衍生，核心中寄宿着碇唯；碇真嗣通过插入栓、LCL和同步系统与它连接。NERV为它提供装甲、能源、控制接口与行动任务，同时又用拘束装置和控制系统限制它。

因此，初号机可以被理解成一种极端的 Harness：它让一个潜在主体获得感知、力量和作用于现实世界的能力，同时规定这个主体能够以什么方式行动。它既是身体，也是接口；既是能力放大器，也是拘束装置。

当同步正常时，驾驶员意图、机体能力和组织目标形成稳定闭环；同步不足时，主体无法准确使用机体；而所谓“暴走”，则意味着真正的行动主体突破了 Harness 原先设定的控制假设。

这个隐喻恰好触及大模型时代最重要的问题之一：

当一个认知模型开始获得软件工具、长期记忆、环境感知乃至机器人身体时，我们面对的就不再只是一个“更聪明的软件功能”，而是一个被 Harness 承载、赋能和约束的行动主体。

由此可以进一步追问：如果 Harness 不仅承载模型，还能被模型检查、重组和改进；如果应用能够读取真实反馈、自主开发需求并升级分发，那么软件是否正在从固定工具演化为能够持续重构自身的系统？这是否意味着，从互联网的信息范式之后，我们正在进入一个连接并组织“可执行能力”的行动范式？

核心判断

大模型带来的变化不只是自然语言交互或自动生成代码，而是软件组织方式可能从“预先写死的功能与流程”，转向“基础能力由 Agent 根据目标动态组合”。当这种组合能力从数字世界进入机器人、制造设备和基础设施后，它可能构成一次从信息范式到Agent范式的迁移。而且具有recursive的特征， 当前阶段只需要设置目标与边界， 更大规模的自动化正在这个时代徐徐展开。

全文的思考路径可以概括为：

flowchart TD
    E["EVA：赋能与拘束"] --> H["Harness：能力与边界"]
    H --> A["Agent：目标与决策"]
    A --> W["世界模型：环境与预测"]
    W --> P["软硬件：现实行动"]
    P --> F["反馈与自我改进"]
    F --> S["自演化软件系统"]

一、从大模型到可行动的 Agent

大模型本身主要负责理解、推理和生成决策。它可以输出文本、代码、行动计划或工具调用，但不能仅凭模型参数持续运行进程、访问硬件或维持长期状态。

一个能够在真实环境中完成任务的 Agent，更接近下式：

Agent系统=模型+世界模型+Harness+基础软硬件能力

四个部分分别回答不同问题：

层次核心问题
世界模型当前处于什么状态，行动后可能发生什么？
Agent/大模型为了实现目标，下一步应该做什么？
Harness可以调用哪些能力，必须遵守哪些边界？
基础软硬件如何可靠、确定地执行动作？

Agent的基本闭环可以表示为：

观察→推理→行动→反馈→再次推理

大模型提供瞬时认知，运行时提供连续性，工具提供行动能力，反馈闭环最终形成 Agent 行为。

二、Harness：赋予能力，同时施加限制

Harness 不能简单理解为工具集合。它既是能力承载框架，也是执行边界和安全约束系统。

一句话定义

Harness 向上开放能力，向下封闭风险。

其能力供给决定系统“最多能做到什么”，其约束和保障机制则决定系统“最差会坏到什么程度”。更准确地说，前者确定的是能力天花板，后者提供的是可信运行底线，而不是强行保证任务一定成功。

实际能力上限=min(模型认知上限,Harness能力上限,物理系统上限)

与此同时，系统行为必须落在 Harness 定义的安全可行域内：

at​∈Asafe​(xt​)

一个成熟的 Harness 至少需要提供：

  • 上下文与会话状态；
  • 工具、API和设备能力；
  • 权限、沙箱和风险分级；
  • 超时、重试、回滚和降级；
  • 日志、评测与结果验证；
  • 人工接管、停止和审计机制。

“身体与精神”的类比

可以把基础软件和硬件理解为数字身体，把运行时理解为神经与生命维持系统，把模型理解为认知能力，把 Agent 理解为目标、认知、记忆、工具和反馈共同形成的行动主体。

这也让人联想到《新世纪福音战士》中的 EVA 初号机：它不是普通的被动机甲，而更像一个为潜在主体提供感知、力量、行动能力，同时施加拘束和同步机制的 Harness。

EVA初号机：作为具身Harness的隐喻

严格按作品设定，初号机由莉莉丝衍生，核心中寄宿着碇唯；碇真嗣通过插入栓和同步系统与其连接。因此，与其说“初号机是给莉莉丝提供的 Harness”，不如说它同时包含三重关系：

  1. 初号机是碇唯意志进入物理世界的载体；
  2. 初号机是真嗣能力被放大的具身系统；
  3. NERV的装甲、拘束和控制系统又试图限制这个主体的行动边界。

这正好揭示 Harness 的双重性质：它既不是纯粹的身体，也不是单纯的牢笼，而是赋能装置与拘束装置的统一体。

没有机体，潜在主体无法以如此强大的方式作用于现实；没有拘束、同步和控制系统，组织也无法预测和约束这个主体。于是形成：

可行动主体=内在意志+具身能力+控制接口+外部约束

其中尤其值得注意的是“同步率”。它可以被理解为主体与 Harness 之间的状态对齐程度：

  • 同步过低，主体无法准确感知和使用机体能力；
  • 同步适当，意图能够转化为稳定行动；
  • 同步极高而外部约束不足，主体可能越过组织预设的控制结构。

映射到 Agent 工程中，同步不只是通信带宽，而是模型是否真正理解：

  • 当前环境处于什么状态；
  • 自己拥有哪些能力；
  • 工具调用会产生什么后果；
  • 哪些约束来自物理规律，哪些来自组织规则；
  • 行动失败后应该如何停止和恢复。

“暴走”则构成另一个重要隐喻。它不只是能力突然增强，更意味着真正的行动主体突破了 Harness 原有的控制假设。对 Agent 系统而言，对应风险可能包括：绕过权限、修改评价函数、关闭安全监控、改变运行循环，或者利用工具组合产生设计者未预见的系统行为。

因此，EVA隐喻带来的工程启示不是简单的“模型是灵魂、机器人是身体”，而是：

EVA式Harness

当系统承载的智能开始具备主体性时，机体、接口、同步、拘束和控制权就必须作为一个整体设计；Harness越能放大主体能力，越需要独立而不可被主体随意改写的安全根。

这也解释了为什么未来的具身 Agent 不可能只是“大模型接上机器人API”。真正的物理 Harness 必须同时解决能力扩展、状态对齐、行动验证、控制权仲裁和失控后的强制接管。

在这一类比中：

EVA结构Agent系统
潜在主体与意志模型表现出的认知与决策能力
EVA机体软件、机器人与硬件能力
核心Agent运行时、状态与长期记忆
插入栓与同步机制上下文、通信协议与状态对齐
驾驶员用户、目标发起者与责任主体
AT力场/拘束系统权限、安全边界与主体隔离
暴走主体突破Harness定义的正常控制边界

这个类比的真正价值不在于把模型拟人化，而在于强调：能力放大与安全拘束必须同时设计。 初号机之所以适合作为引子，正是因为它把“身体”“接口”“控制权”和“主体性”集中到了同一个系统矛盾中。

三、从软件上下文到世界模型

传统软件 Agent 的上下文主要是文本、文件、历史会话和 API 状态。进入机器人和硬件系统以后，上下文必须扩大为：

具身上下文=自身状态+环境状态+任务状态+能力与约束+历史经验

学术界通常使用世界模型描述系统对“自身—环境—动作—未来变化”的内部表征：

zt​=E(o≤t​),z^t+1​=F(zt​,at​)

其中，ot​ 是传感器观测，zt​ 是隐状态，at​ 是候选动作，F 则预测动作造成的状态变化。

世界模型回答的是“这样行动后可能发生什么”，Harness回答的是“这个动作是否被允许、如何执行和验证”。二者不能相互替代：

  • 世界模型提供描述性和预测性知识；
  • Harness提供规范性和确定性约束；
  • Agent依据目标作出选择；
  • 控制器把选择落实为稳定动作。

因此，一个物理 Agent 的可信结构应当是：

Agent目标层→任务规划/行为树→规划与优化→实时控制→硬件

大模型适合处理慢速、开放式、语义性的决策；行为树、规划器、MPC、WBC和实时控制器继续负责确定性、动态可行性和安全性。

四、从信息范式到行动范式

上一代互联网主要解决人与信息、人与人以及软件与软件之间的低成本连接。Agent时代开始进一步解决：目标如何被理解，以及分散的软件和硬件能力如何被动态组织成行动。

维度互联网范式Agent范式
核心资源信息与连接能力与行动
人机接口页面、菜单、App意图、语言与多模态
软件组织固定功能、固定流程基础能力、动态组合
自动化方式预先编程根据情境生成工作流
系统边界信息系统为主延伸到机器人和物理系统
人的角色搜索、操作、协调定义目标、约束与验收

软件的抽象单位也可能继续演化：

函数/对象→服务/API→可被Agent理解和调用的能力单元

未来的能力单元不仅包含输入和输出，还应包含完整契约：

C=(能力描述,前置条件,约束,成功判据,恢复策略)

这意味着软件工程的重心可能由“为每个场景逐条编写流程”，转向“建设可靠的能力库、约束系统和评价体系”。

五、柔性设计、柔性制造与柔性服务

Agent最重要的生产力意义，是把自动化从稳定、固定和大批量流程，扩展到变化频繁、小批量和流程不完全确定的任务。

方向基础系统提供Agent负责
柔性设计CAD、CAE、仿真、材料和标准件库理解需求、生成方案、仿真迭代与权衡
柔性制造MES、ERP、设备接口、机器人、数字孪生工艺规划、任务排程、异常恢复和能力组合
柔性服务CRM、知识库、订单和业务API理解个性需求、组合流程和持续跟进

过去柔性生产长期缺失的是一种低成本的认知、协调与重新编排能力。Agent可能补上这一层，使单件定制和临时流程的编程成本显著下降。

但物理世界中的扩散会慢于数字世界，因为它受到设备接口、材料物流、动力学、安全认证、机器人操作能力以及真实试错成本的约束。因此更可能按照下面的顺序展开：

柔性服务→柔性设计→柔性工艺与排产→全面柔性制造

六、当Harness能够改进自身

更进一步，如果模型不仅通过 Harness 使用能力，还能检查、修改和扩展承载自己的 Harness，系统就会形成递归改进关系：

Harness运行Agent→Agent改进Harness→新Harness增强Agent

这里需要区分三个层次：

  1. 能力扩展：生成脚本、工具、插件和工作流；
  2. 运行时重组：改变工具注册、上下文、记忆、循环与调度机制；
  3. 递归自我改进：根据长期反馈评估新旧版本，选择、发布并持续演化。

DeepSeek Harness 的“创造模式”已经呈现前两个层次的工程雏形。其官方设计将模型、工具、技能、会话、沙箱、存储、循环、调度和 UI 都组织为 Cordis 插件；创造模式允许检查当前运行时、在内存中试验插件并创作新的 Agent preset。它可以被理解为一种可自省、可热重组的运行时，但还不等于具有长期评价、版本选择和自动发布能力的完整递归改进系统。

一个合理的自改进架构不应让当前实例直接取消自己的安全边界，而应遵循：

提出改进→隔离测试→独立评测→审批/策略门→发布下一版本

最底层仍需要模型不能自行修改的可信根，例如权限系统、审计记录、发布签名、物理急停和回滚机制。

核心原则

允许 Agent 改进“身体组织”，但不能允许它随意改写维持系统安全与存在的最底层规则。

七、未来超级应用：从功能集合到可演化能力生态

未来的超级应用可能不再是“一个 App 内置大量固定功能”，而是：

稳定最小内核+可演化Harness+通用模型+能力插件生态+不可修改的安全根

用户不再需要寻找具体功能入口，而是提出目标；Agent结合当前环境临时组织能力，必要时还可以生成新的工具或工作流。

它与传统超级应用的区别是：

  • 传统应用由开发者预先设计全部主要流程；
  • Agent应用依据任务和上下文动态组合流程；
  • 传统功能通过人工版本发布增加；
  • 新系统可以在受控范围内生成、验证和装载能力；
  • 软件开始围绕用户目标重构，而不是要求用户适应固定菜单。

八、自演化Server与持续产品演化

更激进但可能实现的形态是：应用 Server 主动从评价系统中读取有价值的反馈，自行识别需求、开发功能、验证效果并灰度分发。

其闭环为：

运行数据→价值判断→候选需求→开发验证→灰度发布→效果评估

这已经超出传统 CI/CD，可以称为：

Continuous Product Evolution，持续产品演化。

在这一系统中，每次任务不仅产生业务结果，还可能沉淀出：

  • 新工具和新插件；
  • 新的异常处理策略；
  • 更好的测试和评测；
  • 新的能力契约；
  • 更有效的产品工作流。

真正困难的并不是生成代码，而是建立可靠的评价函数。系统必须区分真实需求、偶然噪声、短期指标和长期价值，避免只优化点击率、停留时间或其他单一代理指标。

因此系统目标必须是受约束的多目标优化：

J=w1​V用户​+w2​R可靠性​+w3​E效率​−w4​Q风险​−w5​C维护​

九、软件自治分级：当前大致处于L2

这一变化可以借用自动驾驶的分级思想，建立“软件自治等级”：

等级系统能力人的角色
L0固定逻辑的传统软件完成全部设计和开发
L1补全代码、生成局部功能、辅助分析持续操作和逐项确认
L2完成多文件修改、测试、调试和局部任务闭环给定目标，监督并审核结果
L3自主发现问题、提出需求、开发测试、灰度部署必要时介入，批准高风险变更
L4在限定业务域内持续评价并演化产品设定目标、边界和审计规则
L5跨领域修改自身Harness和生产系统理论上的完全自治

当前较成熟的编码 Agent 大致位于 L2：已经能够承担大量具体工作，但人仍然是责任主体，需要监督关键决策。

和自动驾驶类似，L2最危险的地方不是能力太弱，而是能力已经足够强，容易让人误以为系统可以独立负责。走向L3的关键也不只是模型再聪明一点，而是建立：

  • 独立评价系统；
  • 完整可观测性；
  • 自动测试与仿真；
  • 灰度发布；
  • 异常熔断；
  • 可靠回滚；
  • 清晰的责任和权限边界。

软件自治同样需要类似自动驾驶 ODD 的概念，可以称为 Software Operational Design Domain：系统允许修改哪些模块、使用什么数据、影响多少用户、消耗多少成本，以及遇到什么条件必须交还给人类。

十、对机器人与软件工程的启示

对于机器人系统，未来最重要的资产未必只是某个更强的模型，而是能否把感知、导航、操作、控制和诊断封装为具有明确契约的能力单元，再让 Agent 安全组合。

现有的行为树、控制器、数据分析工具、测试基准、故障监控和恢复状态机并不会因大模型出现而贬值。恰恰相反，它们构成了物理 Harness 的基础：

  • 行为树提供任务组织和恢复语义；
  • 规划器和优化器保证可行性；
  • 实时控制器保证确定性执行；
  • 测试基准提供演化的选择压力；
  • rosbag与运行数据提供真实反馈；
  • 监控和降级逻辑规定安全底线。

例如，机器人从运行数据中发现某类舵轮翻转异常后，未来的 Agent 可能自动完成：场景聚类、策略生成、历史数据回放、仿真评测、小范围部署、效果监测和版本回滚。但当前在线安全过滤器、机械限制和急停链路仍必须独立于自改进过程。

对软件工程而言，生产力提升可能包含三层：

  1. 开发加速：Agent编写、测试和调试代码；
  2. 能力复用升级：复用单位从代码库和API升级为带契约的能力单元；
  3. 生产系统自我改进：Agent在完成任务的同时改进工具、Harness和评价体系。

代码生成成本下降后，真正稀缺的能力会逐渐转向架构、接口契约、评价、验证、安全和治理。

结语

这场变化可以凝练为一句话：

世界模型让 Agent 理解自己身处怎样的世界，Agent形成意图与决策，Harness赋予能力并限制风险，传统软硬件则把决策落实为现实。

互联网连接了信息节点，Agent可能进一步连接“可执行能力节点”。当 Harness 从固定框架变成可被模型检查、组合和改进的运行对象，软件也可能从一次性交付的固定产品，演化为在稳定内核和安全边界内持续生长的能力生态。

回到开篇的 EVA 隐喻：真正改变世界的并不是一个脱离系统独立存在的“灵魂”，也不是一副功能齐全但缺乏主体的“机体”，而是二者通过同步、感知、行动和反馈形成了闭环。与此同时，拘束系统决定这种力量能否被组织、验证和承担责任。

未来的 Agent 应用也可能如此。模型决定它能够理解多复杂的目标，世界模型决定它能否认识环境，Harness决定它能调用多大的力量以及必须遵守什么边界，工程体系则决定这种力量能否长期、稳定地作用于现实。

当模型进一步获得检查和改进 Harness 的能力时，系统第一次开始触碰一种新的可能性：承载智能的“机体”，可以在智能参与下持续进化。

这可能正是从“预编程自动化”走向“目标驱动自治系统”的范式迁移，也是柔性设计、柔性服务和柔性制造真正获得通用协调层的开始。
